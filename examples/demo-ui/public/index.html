Run a real payment

Challenge → sign → serve → settle → ledger read → HCS journal → reconcile. About 21 seconds, end to end.

1 Challenge — HTTP 402
pending

The merchant's /api/quote route, requested with no payment. Waiting to run.

2 Signed — EIP-3009 authorization
pending

The payer signs a ReceiveWithAuthorization locally via createPaymentHeader() — no private key ever leaves this process, let alone reaches this page.

3 Served — HTTP 200
pending

Retried with X-PAYMENT. The resource is served the moment the facilitator verifies the payment.

4 Settled — on-chain transaction
pending

The facilitator submits the EIP-3009 transfer into the non-custodial Escrow contract on Base Sepolia.

5 Escrow ledger — before / after
pending

The merchant's row in the Escrow contract's internal ledger, read directly from the chain.

6 HCS journal — mirror-node read-back
pending

The settlement is journaled to a Hedera Consensus Service topic, then read back independently from the public mirror node.

7 Reconciliation
pending

Three independent sources of truth — the HCS journal, the escrow contract's internal ledger, and its real USDC balance — should always agree.

Security checks

Each of these sends a payment ferry402 is designed to reject. A rejection here is the correct, intended outcome — styled green, not red.
